# 교사(Claude) 설명 생성 지침

각 샘플마다 `distill/work/panel/{id}.jpg` 한 장을 본다. 가로로 세 칸이다.
1. original: 384×384로 통일한 원본
2. grad-cam: MobileViT v2가 "자기 판정" 쪽으로 주목한 영역. 흰 박스가 3번 크롭 위치
3. crop x3: 히트맵 최고점 주변 128px를 3배 확대한 것

함께 주어지는 정보는 MobileViT의 확률(`mobilevit_prob_real`, 1에 가까울수록 실제 사진)과 판정뿐이다.
**정답 라벨은 주지 않는다.** 교사도 눈으로 보고 판단한다.

## 규칙
- 분류기 판정을 따라가지 말고, 이미지에서 **실제로 보이는 근거**로 판단한다. 분류기와 의견이 달라도 된다.
- 근거는 구체적으로 쓴다. "부자연스럽다" 대신 "개의 앞다리가 몸통에 녹아 붙어 있다"처럼.
- 볼 만한 것: 해부학적 오류(손가락, 다리, 눈), 녹아내린 사물 경계, 뭉개진 글자, 반복 텍스처, 조명/그림자 불일치, 비현실적으로 매끈한 표면, 워터마크·JPEG 블록·센서 노이즈 같은 촬영 흔적.
- 모든 이미지는 384 JPEG로 재인코딩됐다. **파일 형식, 해상도, 압축 품질 자체는 근거로 쓰지 않는다.** (저해상도 원본을 확대해 흐릿한 것도 마찬가지)
- 히트맵이 배경이나 의미 없는 곳을 가리키면 솔직하게 "관련 없음"이라고 쓴다. 발표의 핵심 검증 포인트다.
- 확신이 없으면 confidence를 low로 두고 설명도 유보적으로 쓴다. 지어내지 않는다.
- 한국어. 설명은 일반인이 이해할 말로, 3~5문장.

## 출력 형식 (한 줄에 JSON 하나, JSONL)
```json
{"id": "tg0000",
 "teacher_verdict": "REAL 또는 AI",
 "teacher_confidence": "high | medium | low",
 "observations": ["원본에서 본 근거 2~4개, 각각 한 문장"],
 "heatmap_focus": "히트맵과 크롭이 가리키는 곳에 무엇이 있는지 한두 문장",
 "heatmap_useful": "yes | partial | no",
 "agrees_with_classifier": true,
 "explanation": "최종 설명 3~5문장"}
```
