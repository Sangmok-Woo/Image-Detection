# Claude → Qwen2-VL 설명 증류

MobileViT 판정 + Grad-CAM 히트맵 + 히트맵 크롭을 Claude(Opus 5)가 보고 쓴 한국어 설명을
Qwen2-VL-2B에 QLoRA로 옮겨 담는다. 데이터: Hugging Face `TheKernel01/Tiny-GenImage` (CC BY-NC-SA 4.0)

## 흐름
| 단계 | 파일 | 어디서 |
|---|---|---|
| 1. 샘플 1000장 뽑기 + 판정/히트맵/크롭 | `build_samples.py` | 로컬 venv (CPU, 약 40분) |
| 2. 라벨 뺀 배치 만들기 → Claude Code 서브에이전트가 패널을 보고 설명 작성 | `make_batches.py`, `teacher_prompt.md` | Claude Code |
| 3. 합치고 검증·분할해 내보내기 | `export_dataset.py` | 로컬 |
| 4. QLoRA 학습 / test 채점 | `train_qlora.py` | Colab (T4 이상) |

## 설계에서 정한 것
- **형식 누수 제거**: 원본은 진짜=JPEG 직사각형, 가짜=PNG 정사각형이다. 그대로 두면 "파일 형식"으로 정답을 외우므로 전부 384×384 JPEG로 통일했다.
  단, BigGAN(128px)은 확대돼 흐릿해지는 흔적이 남는다. 발표 때 한계로 적을 것.
- **교사에게 정답을 주지 않는다**: 정답을 알고 쓰면 그럴듯한 끼워맞추기 설명이 나온다. 교사는 눈으로 판단하고,
  train/val에는 교사가 맞힌 것만 남긴다. test는 전부 남겨 학생·교사·MobileViT 정확도를 같은 기준으로 비교한다.
- **Grad-CAM은 예측한 클래스 기준**으로 계산한다 (앱의 기존 코드는 항상 REAL 점수 기준).
- 샘플 구성: 진짜 500 + 가짜 500 (ADM, BigGAN, GLIDE, Midjourney, SD15, VQDM, Wukong 균등. 이 조각들엔 SD14가 없다).

## 학습 데이터 한 줄
`images`(원본·히트맵·크롭 3장), `messages`(LLaMA-Factory 호환), `user_text`/`assistant_text`, 정답·생성기·MobileViT·교사 판정.

### 재현 시 주의
- 이미지는 `.gitignore` 대상이라 클론에 딸려오지 않는다. `build_samples.py`로 `std/`를 만든 뒤
  **반드시 `regen_new_model.py`를 돌려야** 커밋된 meta와 일치한다.
  `build_samples.py`는 메모리상의 q90 이미지로 확률을 재고 `std/`에는 q95로 저장하는데,
  `regen_new_model.py`는 저장된 q95 파일을 다시 읽는다. 이 차이로 확률이 평균 0.0165 어긋나고
  판정 3.1%·크롭 26.5%가 바뀐다. 이 순서를 지키면 `pred`·`crop_box`가 1000/1000 일치한다.
- 서브에이전트를 병렬로 돌릴 때 임시 파일명에 **배치 번호를 넣을 것**. 공용 이름(`p1.jsonl` 등)을
  쓰면 서로 덮어쓴다(실제로 3개 배치에서 발생, 전부 자체 복구). `check_detailed.py`의 교차오염
  검사가 최종 산출물을 지켜준다.

### 히트맵 유용성 — 평가 지침에 따라 크게 달라진다
같은 이미지·같은 히트맵인데 1차와 2차 평가가 다르다. 2차 지침에만 "억지로 의미를 부여하지 말라"가 있다.

| | yes | partial | no |
|---|---|---|---|
| 1차 | 42.4% | 46.1% | 11.5% |
| 2차(상세) | **22.3%** | 48.6% | **29.1%** |

이동: yes→partial 220, partial→no 180. **히트맵 유용성 지표 자체가 주관적**이라는 뜻이므로
발표에서 단일 수치로 제시하지 말고 두 값을 나란히 놓을 것.

### Grad-CAM 실패의 정량 근거
- **모서리 집중**: 히트맵 최고점이 네 모서리에 찍히는 비율 **29.2%**, 균등분포 기댓값 11.3% 대비 **2.6배**.
  (변에 닿는 비율 60.1%는 기댓값 55.9%와 큰 차이가 없어 의미 없다 — 모서리가 진짜 신호다.)
  서브에이전트들이 20개 배치 전부에서 독립적으로 보고한 "네 변을 액자처럼 두르는 띠"와 일치한다.
- **분류기가 틀릴 때 히트맵도 못 믿는다**: 분류기 적중 시 yes 26.7% / 오답 시 **13.7%**.
- 실패 유형 3가지: ① 테두리·레터박스·회전보정 여백 반응(원본의 편집 흔적) ② 규칙적 점 격자
  ③ 해석 역전(위치는 정확한데 그 부위가 반대 판정의 근거 — `partial`의 주류)
- ①은 384 JPEG 재인코딩으로 지울 수 없는 **형식 누수의 잔존 형태**다. 한계로 명시할 것.

### 알려진 치우침
`evidence_ai` 빈 배열 304건이 **전부 교사 판정 REAL**이다(`evidence_real` 빈 배열은 4건, 전부 AI).
다만 `assistant_text`는 판정을 근거보다 **먼저** 쓰므로 판정 예측에 누수로 작용하지는 않는다.
바꿔 말하면 현재 형식은 결론을 먼저 내고 근거를 뒤에 쓰는 구조라, 추론 과정 학습 효과가
제한될 수 있다. 근거·판단과정을 앞에 두는 순서를 실험해 볼 여지가 있다.

## 2026-09-27 4차 — Qwen2-VL QLoRA 학습·채점 완료 ✅
전체 경과와 수치는 **[REPORT.md](REPORT.md)** 에 정리했다. 아래는 요약이다.

| | test 100장 정확도 |
|---|---|
| 교사(Claude) | 85% |
| **학생(Qwen2-VL-2B QLoRA)** | **78%** |
| MobileViT | 67% |

- 검증 손실 1.018 → 0.924 → 0.910 → 0.885 → **0.881**(5ep, 최적) → 0.888(6ep, 반등)
- **3에포크와 6에포크의 test 정확도가 78%로 동일하다.** 판정이 바뀐 21건이 개선 10 / 악화 10으로
  상쇄됐다. 검증 손실 개선이 정확도로 이어지지 않는다 — 손실은 설명 전체를, 정확도는 `판정:`
  한 줄만 본다. 증류 목적이라면 3에포크로 충분하다.
- **학생이 교사를 단순 복사하지 않는다**: 교사가 약하고 분류기가 강한 ADM(교사 2/8, 분류기 8/8)에서
  학생은 8/8, 분류기가 망가지는 실제 사진(22/50)에서는 49/50인 교사 쪽으로 기울어 43/50.
  프롬프트에 분류기 판정이 함께 들어가므로 **상황별로 저울질하는 앙상블 동작**이 나온다.

### 실행 시 주의
- `train_qlora.py`는 Colab `transformers` 4.49 기준이었다. 5.x는 `warmup_ratio`를 없애
  `warmup_steps`만 받는다(수정 완료). 그 외 API는 그대로 동작한다.
- `max_new_tokens`가 400으로 고정돼 있었다. 상세 설명은 1200~1600토큰이라 잘린다 → 1800으로 바꿨다.
- 추가 옵션: `--side`(이미지 한 변, VRAM 조절), `--workers`, `--resume`(체크포인트에서 이어 학습).
- RTX 4060 Ti 8GB 실측 피크: 392px 7.95GB / 336px 7.46GB / 280px 7.05GB. 해상도를 낮춰도
  0.9GB밖에 안 준다 — 주범은 어휘 15.2만 크기의 로짓 텐서다. 다른 앱이 VRAM을 쓰면 공유 메모리로
  스필해 43초/it가 113초/it까지 느려진다. 학습 중에는 GPU를 쓰는 앱을 띄우지 말 것.
